Codex setup

Connect Codex CLI to the central mtel-skill-resolver MCP server.

Codex reads all config (including MCP servers) from a single $CODEX_HOME/config.toml, defaulting to ~/.codex. To scope the resolver to this repo only, point CODEX_HOME at a repo-local .codex directory instead of the global one.

1. Add a repo-local config

Create .codex/config.toml at the repo root with the server under [mcp_servers]:

# .codex/config.toml (committed to this repo)
[mcp_servers.mtel-skill-resolver]
url = "https://mcp-registry.internal.company.com/mcp"

2. Launch Codex scoped to this repo

Point CODEX_HOME at the repo-local dir so Codex loads that config instead of ~/.codex:

CODEX_HOME="$PWD/.codex" codex

Tip: put export CODEX_HOME="$PWD/.codex" in a .envrc (direnv) or a project script so it applies automatically whenever you work in this repo.

Recent Codex versions ship a codex mcp add CLI, but it writes to $CODEX_HOME/config.toml and has no project-scope flag. To repo-scope it, combine it with the same CODEX_HOME trick: CODEX_HOME="$PWD/.codex" codex mcp add mtel-skill-resolver --url https://mcp-registry.internal.company.com/mcp. Editing .codex/config.toml directly (above) is the version-agnostic way and is what we recommend.

3. With auth token

If the server sets MCP_AUTH_TOKEN, add the bearer header in the same .codex/config.toml:

[mcp_servers.mtel-skill-resolver]
url = "https://mcp-registry.internal.company.com/mcp"

[mcp_servers.mtel-skill-resolver.http_headers]
Authorization = "Bearer <token>"

If you add a real token, do not commit it — gitignore .codex/config.toml (or keep the token in an untracked override).

4. Verify

Start Codex with CODEX_HOME set as above and run /mcp to confirm mtel-skill-resolver is connected and resolve_skills is listed.

Codex has no SKILL.md concept — after resolve_skills matches skills and fetch-skills.sh pulls them, run generate-agents-md.js to concatenate the skill bodies into a single AGENTS.md at the project root.
